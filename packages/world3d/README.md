# @silver-tongue/world3d

The 3D front end: a three.js street built from the make-it-in-china asset library, driven by
`@silver-tongue/core` exactly as the TUI is (`core.send(input) → GameEvent[]`, then read
`core.state`). Same courses, same settings, same save format, same localStorage keys as
`packages/tui-web`, so a game started in the browser TUI continues here and back (see Courses and
reading languages).

## Run

Node 22 or later. System Node is older, so these commands put a local Node 22 first on `PATH`:

```sh
export PATH="$HOME/.local/node22/bin:$PATH"   # Node 22 LTS unpacked from nodejs.org's linux-x64 tarball

npm ci                                   # once, at the repo root
npm run build:course                     # content -> dist/courses/index.json + <course>/<learner>.json (required)
npm run dev -w @silver-tongue/world3d    # build + serve on http://localhost:8173/ (PORT=... to change); rebuilds main.js on save
npm run build -w @silver-tongue/world3d  # dist/: index.html, main.js, courses/, assets/, manifest, icons (clips: see Audio)
npm run assets:sync -w @silver-tongue/world3d  # refresh assets/ from the make-it-in-china library
npm test && npm run typecheck            # includes this package's smoke test and tsc -p packages/world3d
```

The GLBs the game uses are vendored in `assets/` (only the ones `src/layout.json` uses, with an
`index.json` listing only those), so the build and the tests need nothing outside the repo. They
are generated by make-it-in-china `tools/blender/build_all.py`; don't hand-edit them. After the
library changes or `layout.json` starts using a new asset, refresh them with
`npm run assets:sync -w @silver-tongue/world3d` (copies from `WORLD3D_ASSETS`, default `../assets`
next to the repo checkout). `WORLD3D_ASSETS` also overrides the build's and the tests' source.
GLBs are served as files, never inlined. Current build: about 10.0 MB in total (10,266 KB; main.js about
778 KB including three.js, courses/ about 0.3 MB of course files, 104 GLBs about 9.1 MB: Main Street, Station Road,
five rooms, their furniture and props, and 18 rigged characters and pets, the humans at about 0.4 MB each,
the bulk). Just under 10 MiB, so no Draco/meshopt compression yet: the budget is 15 MB (if it grows past 10 MB, run gltf-transform
`optimize --compress meshopt` in `scripts/sync-assets.mjs` and load with three's MeshoptDecoder).

**Audio clips** (`content/audio/<language>`, for zh 870 clips, all referenced by the course, about
7.1 MB) would take dist/ to about 17.4 MB, past the 15 MB budget, so a one-off build doesn't copy
them: the page loads each clip by URL as it is said, from `../courses/<course>/audio/`, the browser
TUI's copy at the Pages site root (tui-web's build copies them to its `dist/courses/<course>/audio/`).
`npm run dev` and `WORLD3D_AUDIO=bundle npm run build -w @silver-tongue/world3d` copy the clips each
course uses into `dist/courses/<course>/audio/` and load from there (a self-contained dist/ to host
alone). Clips missing (dist/
served on its own without them): three failed loads in a row and the game plays silently, the
HUD saying "no audio".

## Deploy (GitHub Pages)

`.github/workflows/pages.yml` builds the course, the browser TUI and this package on every push to
main and uploads one site: `packages/tui-web/dist` at `/`, `packages/world3d/dist` at `/world3d/`.
Every world3d URL is relative (`./main.js`, `./assets/...`), so it works under any subpath,
including a fork's `<user>.github.io/silver-tongue/world3d/`. `index.html` carries a web manifest
(`src/manifest.webmanifest`, fullscreen), theme colour and the apple-mobile-web-app tags, so "Add
to Home Screen" opens it fullscreen; the icons in `icons/` are made by
`scripts/make-icons.py` (Pillow + a Noto CJK font; checked in). They sit outside `src/`, which
upstream's `tools/test/language-free.test.ts` keeps free of any particular language.

## Phone play

- **Input** (`src/input.ts`, `src/touch.ts`): one `MoveInput` vector fed by WASD / arrows and a
  floating joystick. A touch landing in the left half (under the HUD) that is held past 200 ms or
  dragged 10 px or more becomes the joystick, drawn where the thumb landed (radius 60 px, 18% dead
  zone, a half push walks at half speed); a shorter, stiller touch anywhere is a tap (tap-to-walk,
  tap an NPC). Mouse clicks have no time limit. The right-side action button mirrors the prompt
  ("E · Talk to Wang"); the action column's notebook button is 56 px. Both sit inside the safe
  area. The touch look (`html.touch`) switches on at the first touch or on a coarse pointer.
- **Layout** (`src/ui/viewport.ts`): on a phone (short side at most 540 px) the panels are placed
  from computed rects written as CSS custom properties. Portrait: one HUD chip row with short
  wording, the objective one line with an ellipsis, the reply panel a bottom sheet (at most 45% of
  the height, scrolls), the bubble between them. Landscape: reply panel and lists in the right
  third. The bubble is clamped inside its area; a head that projects off-screen pins it
  top-centre. No pinch / double-tap zoom or pull-to-refresh (`touch-action`, `overscroll-behavior`,
  iOS gesture events).
- **Camera:** in a portrait scene it pulls back (0.78 instead of 0.6 of the follow distance) and
  lifts the picture 16% so player and NPC sit above the reply sheet. Pixel ratio capped at 2;
  outlines thicker on phones (`camera.ts outlineScale`).
- **Performance:** every space's static meshes (ground, tiles, buildings, props) are merged per
  material at build time (`world.ts mergeStatic`); characters and what they hold stay separate.
  Street: 787 draw calls (unculled) before, 208 after; interiors 105-182 before, 37-46 after.
  `world3d.info()` shows the frame's calls and the batching figures.
- **Audio:** mobile browsers refuse `play()` until a gesture has played the element: each tap /
  click / key (touchend, pointerup, click, keydown, capture phase) plays a silent WAV through the
  page's one audio element until one goes through (`src/audio.ts unlock`). A line said before
  that (a save resumed mid-scene) is skipped silently; the text is on screen.
- Debug: `world3d.touch()` gives the last joystick vector, pointers down and the layout in use.

## Architecture

```
courses/<id>/<learner>.json (courses.ts) ─► core ◄─ inputs ── game.ts ── UiModel ──► ui/ (HTML overlay)
                  └── events ──►    ▲                 └► main.ts ──► world.ts / player.ts / camera.ts (three.js)
                                    └── world actions (zone entered, NPC tapped, reply picked)
```

- `src/courses.ts`: which course the page plays, picked and loaded as tui-web's `boot` /
  `fetchCourse` (see Courses and reading languages). DOM-free; `src/ui/start.ts` is its start list.
- `src/game.ts`: the only module that talks to core. No DOM, no three.js, so it runs under vitest.
  - `dispatch(events)` is the one event dispatcher. Its `switch` covers every `GameEvent`, and the
    `never` default fails the typecheck when core adds an event.
  - Inputs (see Parity below; `INPUT_AFFORDANCES` is typed over `Input["type"]`):
    - `enterPlace` sends `goTo` one hop at a time along the world graph. It is idempotent (already
      there: nothing) and not re-entrant (a call from a change handler while hops are being sent is
      dropped). The street doesn't mirror the graph: the room is off Market Street, so walking into
      its door from Main Street sends market, then room.
    - `travel` lists every other place (the TUI's "Go to" items, routed); choosing one goes through
      `enterPlace`.
    - `talkTo` follows the scene start sequence of `packages/tui/src/app.ts`.
    - `reply`, `replyTiles` (tap tiles in order), `giveUpTiles`, `helpWord` (logged as help, like
      the TUI's word help), `sleep`, `visitMentor`, `setName`.
  - The model also carries the objective line (`src/objective.ts`), the day summary card
    (`dayCard`, from `dayEnded` and the day's `walletChanged`), wallet floats (`walletFx`, with a
    label for shopping and for a delivery's wages), a notebook pulse counter (a word goes in or
    becomes known), mix-ups (the NPC shrugs), the parcel being carried (`hud.errand`, from core's
    `state.errand`) and the price of the reply in progress (`reply.cost`, a variant's `cost`).
  - `openSession` uses tui-web's `WebSessions` for storage (new game, a chosen session, or the
    last played).
- `src/layout.json`: owned spatial data.
  - `places.<name>`: its buildings, the `space` its trigger is in (default Main Street), and either
    a trigger `zone` (x/z box; `zones` adds more boxes of the same place, e.g. Market Street
    wrapped round the shop door and the gate) or an `interior` (a space of its own) plus the `door`
    into it (`{building, anchor: "door", width, depth, shift?}`: the trigger box `depth` metres out
    from the door anchor, `shift` across, on reachable ground).
  - `interiors.<id>`: every scene space other than Main Street, entered through its place's door.
    A room: `shell` (an interiors/ shell: its `furniture_slots` become pieces, ids
    `<shell id>:<asset>[:n]`), or `size` + `ground` boxes (the warehouse, the shop, the stairwell).
    `outdoor: true` makes it a side street instead (Station Road): `buildings` (blocked by
    footprint, like Main Street's), `tiles`, `walkers`, `surfaces` (kerbs), sky and fog, the full
    day's light. `entry` (a shell anchor or a fixed stand, moved `inset` in and `shift` across) is
    where the player comes in; the whole open front edge (`exitDepth` deep), or `exitBox`, leads
    back out to the place outside its door. Its own places' zones and doors sit in it the same way
    (the tea house door and the school / hospital / station zones on Station Road; the stairwell
    door in the room's back wall). Extra `pieces` (counters, shelves, box stacks), `dressing`,
    `interactables` (`sleep`, `notebook`), `camera.distance`, `background`. The hideable +x wall is
    never drawn.
  - `npcs.<name>`: character GLB, the building / piece it stands at and its stand anchors
    (`npc_stand`, `player_stand`), or fixed stands plus `space`. `heldProp`: a string (a hand prop:
    idle / talk) or `{asset, carry: true}` (boxes, bags: the carry pose).
  - `player.errandProp`: what the player carries while an errand is on (`delivery_bag`, carry).
  - `walkers`: ambient characters pacing x/z waypoint paths there and back. `dressing` entries with
    `behaviour: "scatter"` (the pigeons) dart away from the player.
  - Street tiles, ground boxes and dressing were ported from the Blender mock-up
    (`tools/blender/mockup.py`, via `assets/street_mockup.glb`) by `scripts/port-mockup.mjs`. The
    JSON is now the source of truth: edit it by hand. Re-running the port overwrites it and drops
    `interiors`, `walkers`, the doors and the NPC changes; don't, or merge them back.
- `src/layout.ts`: pure maths on the layout. `anchorToWorld` is the one anchor → world transform.
  `LayoutIndex.space(id)` normalises the street and each interior into one `SpaceLayout` (pieces,
  tiles, ground, dressing, walkers, triggers, interactables, NPCs, bounds, floor height). Also
  `stand`/`npcStand`/`talkStand`/`spawn`/`entrySpawn`/`exitSpawn`/`arrival`, `triggerAt` /
  `placeAt` (per space), `heightAt`, `sizeBlocker` (interior furniture from its index size) and
  `assetNames` (a scan of the whole layout; `build.mjs` has the same scan). `route` finds place hops.
- `src/spaces.ts` (pure):
  - `ZoneTracker`: the edge-triggered current zone. A trigger counts only 0.25 m inside it
    (`ZONE_MARGIN`), leaving counts only 0.25 m outside every trigger; in between the previous zone
    holds. After a change there is a 0.5 s cooldown. So a position jittering on a boundary sends no
    goTo, and big swings every frame are rate-limited.
  - `SpaceNav`: which space the player is in. `step` per free frame → a place for `enterPlace`;
    `sync(place)` after core moved them → the arrival (space + stand) when another space shows that
    place: into a space at its entry, back out past the door just used (Station Road → Market
    Street at the gate, the tea house → Station Road, the stairwell → the room).
  - `promptTargets` / `nearestPrompt`: the one prompt resolver (talk, enter, leave, sleep,
    notebook). The bed offers sleep only where core allows it (`UiModel.canSleep`).
- `src/objective.ts`: the one objective resolver, from core state alone: the name first; a parcel
  to deliver ("Deliver the parcel: go to Hospital and find Doctor"); a story scene here, else the
  nearest one elsewhere ("Go to Noodle Shop and find Cook"); the mentor's notes; paid shifts;
  practice; "go home and sleep". The sub-line is the rent timer.
- `src/carry.ts`: `PlayerCarry` puts `player.errandProp` in the player's hand while the model has an
  errand (synced after every change, so a restored save has it too) and takes it away after.
- `src/streetlife.ts` (pure): `WalkerMotion` (waypoints there and back, stop and wait while the
  player is within 1.3 m ahead) and `ScatterMotion` (away from the player within 2 m, home after).
- `src/world.ts`:
  - `AssetCache` is the one GLTF loader. It loads each template once and clones it per instance
    with `SkeletonUtils.clone` (skinned meshes bind to the instance's own bones), sharing geometry
    and materials. It keeps the GLB's clips on the template (`animations`).
  - Toon look: `MeshToonMaterial` with a 3-step gradient map, one material per palette colour.
  - Outline: inverted hull. Skinned meshes get a skinned hull on the same skeleton.
  - `SceneSpace` builds any space from its `SpaceLayout`: its own `THREE.Scene`, lights, blockers
    (street buildings: footprints cut 0.35 m short of their `player_stand`; interior furniture:
    index sizes; a small box per NPC), picking (NPCs, interactables, then the floor), NPCs, extras,
    walkers and scatterers, the day tint (`setDaylight`) and shrugs. Every space is built at start,
    so a door is instant behind a 0.7 s fade.
- `src/player.ts` + `src/movement.ts`:
  - Walking: tap to walk in a straight line, sliding along blockers, or WASD/arrows relative to the
    screen. The player walks in the current space's `WalkArea` (bounds, blockers, floor height).
  - The character faces its movement direction; its `CharacterActor` animates (see Animation).
- `src/camera.ts`: a fixed high three-quarter view (elevation 42°, azimuth 36°, as in
  `tools/blender/lib/sheet.py`). It follows the player with damping and closes in on player + NPC
  during a scene. Interiors set a shorter distance (`camera.distance`); on a portrait phone it pulls
  back 25% so the room's width fits. `CAMERA.mode = "orbit"` is the one-line switch to Jamil's
  orbit camera.
- `src/ui/`: the HTML/CSS overlay. No text is drawn in WebGL.
  - HUD: place, day, wallet, slots left, rank, the ♪ sound chip (tap: on / off), and a parcel chip ("Parcel for School") while an
    errand is on; under it the objective line and the rent timer.
  - Place banner (name + description) on entering a place.
  - The floating prompt: one button over the nearest thing to use, "E · Talk to Old Wang",
    "E · Enter Noodle Shop", "E · Leave for Main Street", "E · Sleep", "E · Read your notebook".
    Tap it or press E.
  - Speech bubble anchored to the NPC's `HeadTop` bone, projected every frame. It shows the line
    as written. Tap a word for its readings and gloss (every `Word.readings`, as the TUI's word
    help; and hear it; ▶ in the popover says it again), or "…" for the whole sentence's meaning and
    reading (each word's last reading, as the TUI's [s]; said aloud). ▶ says the bubble again. New
    words get a faint underline. Replayed (slowed) lines show each word's last reading as ruby.
    Tiles are joined with spaces in a spaced language (`joinTiles`), as core judges them.
  - Reply panel: pick mode (a ▶ per option that says it without picking, a "?" word-help toggle), or tiles
    mode (tap tiles in order, Undo, Say it, Give up). A reply that buys something shows its price
    in the title ("Costs ¥4").
  - Toasts show narration, results and rejections. Wallet changes float "+¥5" / "−¥2" from the
    wallet chip ("−¥4 shopping", "+¥14 delivery"). The notebook button pulses when a word goes in.
  - Talking to someone whose only scene waits for money says so, as the TUI menu's
    "Shopkeeper: Buy something · needs ¥5" line.
  - Scene list (an NPC with several things to talk about), travel list ("Go to…").
  - Notebook: `packages/tui`'s `notebookLines`, rendered as HTML (button, N, or the notebook on
    the room's desk).
  - Day summary card after sleeping: earned, mix-ups, food, rent (or "not paid"), change, wallet.
  - Menu: saved games (tui's `sessionLines`), export / import a save line (tui's
    `encodeSave` / `decodeSave`, same `st1:` lines as tui-web and the terminal game), new game,
    sound on / off, how to play.
  - Name prompt, mentor button, sleep button (at home only).
- `src/anim.ts` + `src/actor.ts`: character animation (see Animation).
- `src/strings.ts`: text in two layers. `s(id)`: strings the learner FTL doesn't have yet.
  `display(t)`: learner messages reworded for 3D (`TEXT_3D`: the TUI's "Press [w] … [s]" becomes
  "Tap a word … the “…” button"). A `w3d-<id>` message in the learner FTL overrides either. A test
  checks that no learner text the 3D world shows has a TUI key hint.

Scene start sequence (from app.ts): core has no `talkTo` input. Tapping an NPC, or pressing E /
tapping the prompt within 2.3 m of one, lists the scenes where `availableSceneIds(course, state)` gives
`scene.place === state.place` and `scene.npc === npc`. It adds the mentor's "ask about the
language" option when that NPC is the mentor and notes are waiting. With one item it sends
`startScene` (or `visitMentor`) straight away. With several it shows a list. With none it shows a
"nothing to talk about" toast. Tapping an NPC from further away first walks to their building's
`player_stand` and talks on arrival.

## Animation

Rig contract (the Blender rig export): a human GLB has one skinned mesh and an armature, with
clips `idle`, `walk`, `talk`, `carry_idle`, `carry_walk` (pets: `idle`). Clips are 24 fps, loop
seamlessly and walk in place. Bones `HeadTop`, `RightHandGrip` and `LeftHandGrip` anchor the
speech bubble and held props. `rig.stride_m` in the characters manifest (so in `index.json`) is the
distance one loop of the walk clip covers.

- `src/anim.ts` (pure, tested in `test/anim.test.ts`):
  - `AnimMachine` / `nextState`: moving wins (`walk`, or `carry_walk` when holding a prop), then
    talking (`talk`), then `carry_idle` or `idle`. Walking starts above `WALK_ON` (0.3 m/s) and
    stops below `WALK_OFF` (0.15 m/s), so it doesn't flicker. There is no carry-talk clip: a
    character holding a prop talks with `talk`, and the prop stays on the grip bone.
  - `clipFor`: a missing clip falls back (`carry_*` to the plain clip, `talk`/`walk` to `idle`),
    so pets and partial rigs just idle.
  - `walkTimeScale(speed, stride, clipSeconds) = speed / (stride / clipSeconds)`: the walk clip's
    playback rate at which the feet cover the ground speed. The actor applies it each frame from the
    measured speed. Without `rig.stride_m` it uses `DEFAULT_STRIDE` (1.3 m).
- `src/actor.ts`: `CharacterActor` wraps an instance in a `root` group (owners move and turn it).
  It runs an `AnimationMixer` and crossfades (`FADE`, 0.2 s) on every state change. `hold(prop)`
  puts a prop (origin at its grip) on `RightHandGrip` and sets the carry flag. `headTop()` returns
  the `HeadTop` bone's world position. A GLB with no clips falls back to the old procedural bob and
  lean. With no `HeadTop` bone, the head position falls back to the manifest `head_top` height.
  With no grip bone, the prop isn't shown.
- Who plays what:
  - Player: idle / walk from its ground speed. It stays on idle during a scene, facing the NPC.
  - NPCs idle at their stand. Within `FACE_RANGE` (3 m) of the player, and always during their
    scene, they turn smoothly to face the player; otherwise they turn back to the stand's facing.
    During their scene they play `talk` while their line is in the bubble (`Street.setTalking`,
    set from the model in `main.ts`).
  - Held props come from `layout.json` `npcs.<name>.heldProp` (and `walkers[].heldProp`, through
    the same `heldProp()` reading); see the table below. These are hand props: the NPC keeps
    idle / talk. Only `{asset, carry: true}` (boxes, bags) plays `carry_idle` / `carry_walk`: the
    player's parcel (`player.errandProp`, `delivery_bag`) during an errand. The build copies them.
  - Mix-ups (a reply that did the wrong thing): the NPC shrugs. The rigs have no `shrug` clip, so
    it is `talk` plus a head shake on the `Head` bone for 1.1 s; a rig that brings a `shrug` clip
    plays that once instead.
  - Walkers play walk (at their ground speed) and idle while waiting; pigeons idle and hop as they
    scatter; the cat, the courier and other street extras play `idle` in place.
- Debug: `world3d.anim()` in the browser console lists each character's state and clip (NPCs:
  `carrying`, `shrugging`; walkers: `waiting`).

## Parity with the TUI

Every `Input` in core, the TUI action that sends it, and its 3D affordance. `test/parity.test.ts`
reads the `Input` union from `packages/core/src/types.ts`, checks it against `INPUT_AFFORDANCES`
and this table, and plays each one through the Game API (and every `GameEvent` has a dispatcher
case).

| TUI action (packages/tui app.ts, tui-web) | 3D affordance | core input |
| --- | --- | --- |
| menu "Go to <place>" | walk into a zone (Market Street), a street door, or an interior's open front; "Go to…" list | `goTo` (hop by hop) |
| menu "Talk to <npc>: <scene>" | tap the NPC, or E / the "Talk to" prompt within 2.3 m; a list when there are several | `startScene` |
| number keys in a scene (pick) | tap a reply, or 1-4 | `reply` |
| tile numbers, backspace, enter (tiles) | tap tiles in order, Undo (Backspace), Say it (Enter); Give up sends an empty reply | `replyTiles` |
| [w] word help, then a number | tap a word in the bubble; "?" then a word in a reply | `helpWord` |
| [s] whole sentence (in word help) | the "…" button on the bubble (not logged as help, as in the TUI) | none |
| menu "Ask <mentor> about the language" | the mentor button, or talking to the mentor | `visitMentor` |
| name prompt | name dialog | `setName` |
| menu "Sleep" | the bed in your room (prompt / tap), or the Sleep button at home; day summary card after | `sleep` |
| [n] notebook, [↑↓] scroll | Notebook button, N, or the notebook on the room's desk; scrolls natively | none |
| menu "Save and quit" / [q] | nothing to do: every accepted input is saved | none |
| tui-web New game | Menu → New game | none |
| tui-web Games (resume) | Menu → Games | none |
| tui-web Export / Import | Menu → Export (copy the `st1:` line) / Import (paste one; added as a new game) | none |
| status line (day, slot, wallet, rank, rent due) | HUD chips + the objective line's rent timer | none |
| status line "· parcel", menu "You have a parcel to deliver." | parcel chip naming where it goes, the objective line, the bag in the player's hands (carry clips) | none |
| menu "<npc>: <scene> · needs ¥N" (a scene waiting for money) | the same line as a toast on talking to that NPC; a reply's price in the reply panel | none |
| start list "Choose a course" (several courses, none remembered) | the start dialog before the street loads (`src/ui/start.ts`); a failed load says so and the list stays | none |
| settings remembered (`silver-tongue:settings`: course, reading language) | the same key and helpers (`loadWebSettings` / `saveWebSettings`, `chooseStart`, `learnerFor`) | none |
| [o] settings: switch course, reading language, sound | not yet: sound is the ♪ chip / Menu → Sound; course and reading language follow the remembered settings (switch them in the browser TUI) | none |
| [m] sound on / off; bottom right "♪ [m]" / "♪ off [m]" / "no audio" | the ♪ chip in the HUD (tap: on / off; "no audio" when there's none), Menu → Sound, or M | `setSound` (not logged; `state.sound`) |
| lines said as they come (line clips; reactions in each NPC's voice, `reactionAudio`; the player's reply, picked or right tiles) | the same, through `src/audio.ts` (one element, clips in order with a 300 ms beat, slow repeats at 0.8) | none |
| [r] say the last line again (slowly after a slow repeat) | ▶ on the bubble, or R | none |
| [s] whole sentence says the line; [p] play the word / sentence looked up | "…" says the sentence; ▶ in the gloss popover; ▶ on each reply option says it without picking | none |

Every `GameEvent` is handled in `game.ts` `dispatch`: placeEntered (banner), sceneStarted,
lineSpoken / npcReacted / lineRephrased (bubble), replyOptions (panel), actionPerformed (narration,
mix-up shrug), walletChanged (toast + float + day card), trustChanged, wordStateChanged (notebook
pulse), sceneEnded, unlocked, rankChanged, dayEnded (night fade + card), noteReady, playerNamed,
mentorVisited, errandStarted (toast; the bag goes into the player's hands, HUD chip, objective),
errandEnded (toast; the bag is put down, the wages float as a delivery), inputRejected (toast),
soundSet (the HUD's ♪ chip from `state.sound`; off stops what is playing). What is said is
queued per call as app.ts does (lineSpoken, lineRephrased slow or not, npcReacted's
`reactionAudio[reaction][npc]`, actionPerformed on right tiles) and played once the batch is in.

## Courses and reading languages

As the browser TUI (0.13): `src/courses.ts` `pickCourse` fetches the catalog `courses/index.json`,
then `chooseStart` (from `@silver-tongue/tui`) picks the remembered course (settings key
`silver-tongue:settings`, shared with tui-web) or the only one, in `learnerFor`'s reading language;
with several courses and none remembered, the start dialog lists them by `courseLabels`, in the
first course's reading language, and nothing is remembered until one is chosen. The course file
`courses/<course>/<learner>.json` is fetched and tui-web's `migrateWebAliases` moves games saved
under the course's old ids (`aliases`: 0.12's `zh-china-en`) to its own keys, so an old save plays
on as the last game. The page's `lang` is the reading language, and the learner text uses its
locale. The page needs a web server (it fetches its course); the build copies the repo's
`dist/courses/` into `dist/courses/`. Switching course or reading language in play ([o] in the
TUI) isn't there yet.

## Gaps in core (mapped, not changed)

- Entering / leaving a building has no input of its own: doors and interiors' open fronts send
  `goTo` (routed hop by hop), so an interior is simply the place core already has.
- There is no buy input: buying is a scene (the corner shop), whose right reply spends the
  variant's `cost` (`walletChanged` "shopping"). Food is taken at night by `endDay`.
- Errands have no input either: a scene starts one (`errandStarted`), its drop-off scene ends it.
- The day card's "change today" is tracked by the front end per session; core has no per-day
  ledger.

## Stubbed in this slice

- **Settings:** no in-game switch of course or reading language (the TUI's [o]); the start list is
  a plain dialog.

- **Gestures:** no gesture on `npcReacted` beyond the mix-up shrug; `actionPerformed` has no prop
  animation, only narration.
- **Audio:** no per-clip volume or speed control beyond the TUI's (slow repeats at 0.8).
- **Movement:** no navmesh. The mock-up's
  power-line wires aren't drawn. Walkers don't avoid street furniture beyond their hand-laid paths,
  and walk through stools (stools and other small furniture don't block).
- **Day card:** "change today" counts from the start of the day in this session (a game resumed
  mid-day counts from the resume).

## Adding a place or NPC

1. Add it to `content/settings/<setting>/world.json` (core side) and run `npm run build:course`.
2. Place on the street: add the building to `layout.json` `buildings` (`id`, `asset` from
   `index.json`, `pos`, `rotY`). Then add `places.<name>` with `buildings: [id…]`,
   `spawn: {building, anchor: "player_stand"}` and a `zone: {min:[x,z], max:[x,z]}` (the pavement
   in front of it, reaching past its `player_stand`, clear of every other trigger by 0.5 m).
3. Place with an interior: `places.<name>` gets `interior: "<id>"`, `spawn: {interior: "<id>"}`
   and `door: {building, anchor: "door", width, depth: [from, to]}` (on reachable pavement). Add
   `interiors.<id>`: `place`, a `shell: {id, asset}` from interiors/ (or `size`, `floorY` and
   `ground` boxes), `entry: {anchor: "entrance", inset, shift}`, `exitDepth`, `pieces`,
   `dressing`, `interactables`, `camera.distance`.
   A place on a side street or inside another space: `places.<name>.space: "<space id>"`, with its
   zone or door in that space's coordinates (the school on Station Road, the stairwell's door in the
   room). A new side street: an `interiors.<id>` with `outdoor: true`, `buildings`, `tiles`,
   `ground`, `surfaces`, a fixed `entry` and an `exitBox`, and a `door` on the street for its place.
4. NPC: add `npcs.<name>`: `character` (a characters/ asset), `building` (a street building or an
   interior piece id), `stand: "npc_stand"`, `playerStand: "player_stand"` (or fixed
   `{pos, facing}` stands plus `space`), `heldProp` (optional; `{asset, carry: true}` for boxes and
   bags). Positions come from anchors through `anchorToWorld`, never hand-typed where an anchor
   exists.
5. `npm test`. The layout tests check, then the build copies any new GLBs:
   - every place and NPC in the course has a layout entry, every asset is in `index.json`
   - every NPC stands in the space of its place and talks from inside that place; spawns too
   - no two places' triggers in a space overlap (grown by the hysteresis margin); every place has a
     space whose spawn is at that place; every space is reachable from the street
   - every interior's entry is clear of its exit and its furniture, NPC talk stands are free, the
     bed / notebook are reachable, the street exit spawn is clear of every door
