The user wants the merchant story combined with the last stable door lab, with the existing private room included. This supersedes the previous exclusion of merchant-town. Implementation choices below are the builder’s choices under the existing instruction to start without further interviews.

Preserve the actual stable door opening, papers, choices, word explanations, and Min-jun’s reciprocal language exchange. The merchant branch descends directly from the stable door commit without changing its existing game code. Use that branch’s source as the frontend baseline and make an explicit continuation after room-minjun is completed. Carry the player’s name, wallet, and game calendar once; do not pay a wage twice or repeat the opening. Merchant preparations, Korean offers, changing needs, reserved agreements, delivery, and the town ending remain playable.

Use the independent make-it-in-china-room project as the combined application. Its existing launcher opens one game page. The door and merchant builds run inside the page; the private room, scenes, and editable bible open in a side panel without unloading the game or losing an unfinished offer. Small adapters publish played state and witnessed dialogue to the same local server. This is a continuous progression with shared state, not a collection of links. Keep the source app and source game checkouts unchanged.

Canonical character files and live bible editing remain authoritative for AI conversations. Add the source merchant as The Merchant with a sourced profile and no invented proper name. All cast icons remain faceless. Only a character’s own witnessed gameplay dialogue enters their prompt; do not give all NPCs the player’s private exchanges, drafts, future story, or the full author bible. Bundle the game sources and local private core under game/ so build and runtime do not depend on sibling source checkouts. Retain licenses. Builds and game saves must use project-local files; provider CLIs/accounts remain machine services. Keep existing chat and edits; maintain browser door and merchant saves under combined-only namespaces. A new door save starts a fresh linked merchant chapter while previous browser saves remain preserved.

The page should open directly into play. A compact header shows the current chapter and buttons for Private room, Bible, and Scenes. Opening a panel preserves the game mount; closing returns focus. Mobile uses the available screen for the panel and restores the game when closed. Loading, failed saving, and failed continuation must be explicit and recoverable.
